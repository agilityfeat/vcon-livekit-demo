How this demo works

🩹 The live human doctor is stubbed. This call is patient ↔ intake bot only. The doctor does not join the call live — they are an asynchronous viewer who opens the produced record later on the Records page. → Production: real live consultations and/or a clinician queue, with the record still produced for the audit trail.

🩹 No authentication. Anyone who can reach this page can place a call and anyone can read any record; the role is a UI route. → Production: authenticated patients, server-minted tokens bound to a verified record, and role-gated, audit-logged record access.

🩹 No-build client. The LiveKit browser client is imported from a CDN via ESM so the demo needs no bundler. → Production: a pinned, bundled client served from your own origin.

This page needs the same real LiveKit credentials as the agent worker (LIVEKIT_URL / LIVEKIT_API_KEY / LIVEKIT_API_SECRET in .env). Start the agent worker in another terminal so the bot is in the room to greet you.
